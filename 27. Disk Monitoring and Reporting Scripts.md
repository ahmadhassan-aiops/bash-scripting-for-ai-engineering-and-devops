# 27. Disk Monitoring and Reporting Scripts

## Checking Services and Processes

Check whether a service is active:

```console
[root@client1 bash]# systemctl is-active docker
active
```

Check whether a process is running:

```bash
ps -aux | grep nginx | grep -v grep
```

## Removing the Header from Command Output

```bash
df -h | awk 'NR>1'
df -h | awk 'NR!=1'
df -h | tail -n +2
```

`tail -n +2` starts the output from the second line, so these three commands give the same result:

```
tail -n +2  ==  awk 'NR>1'  ==  awk 'NR!=1'
```

## Working with Disk Usage

Replace the percentage sign in the `df -h` output:

```bash
df -h | awk 'NR>1' | sed 's/%/new/g'
```

Print only the partitions whose usage is greater than 40%:

```bash
df -Th | tail -n +2 | sed s/%//g | awk '{ if ($6 > 40) print $6 }'
```

## Proactive Monitoring

An alert on its own is not enough. We also want the issue fixed when the alert fires.

- An L1 engineer usually forwards a monitoring alert (from PRTG, Nagios or Grafana) to the L2 and L3 engineers.
- **Proactive monitoring** means solving the problem at the moment the alert is raised, before it turns into a crash or a performance issue.

**Useful commands:**

```bash
du -sh <file_name>      # size of a file
```

```console
[root@client1 practice]# date +%d-%m-%y-%H
29-06-23-17
```

The date, month, year and hour are used in the script below to name the backup.

## Script: Archive a Log File When the Disk Is Full

The script checks the usage of the root partition. If it is above the limit, it takes a backup of the log file and then clears it.

```bash
#!/bin/bash
status=$(df -h | grep -wi / | awk '{print $5 }' | tr '%' ' ')

time=$(date +%d-%m-%y-%H)

if [[ $status -le 60 ]]
then
        echo "$status : size is good"
else
        cd /opt
        tar cvf - messages | gzip -c > /bash/practice/messages.txt-$time.tgz
        echo "" > messages
        echo "$status : disk space full"
        echo "var log alert has been archieved "
fi
```

```console
[root@client1 practice]# ./disk_log.sh
messages
67  : disk space full
var log alert has been archieved
[root@client1 practice]# ls
disk_log.sh  log.txt  messages.txt-29-06-23-17.tgz
```

## Task: Turn `df -h` into a CSV Report

Take the output of `df -h` without the header, convert it into CSV, and add a serial number at the start of each line.

**Solution with awk:**

```console
[root@client1 practice]# df -h | tail -n +2 | awk '{print NR","$1","$2","$3","$4","$5","$6 }'
1,devtmpfs,895M,0,895M,0%,/dev
2,tmpfs,910M,0,910M,0%,/dev/shm
3,tmpfs,910M,11M,900M,2%,/run
4,tmpfs,910M,0,910M,0%,/sys/fs/cgroup
5,/dev/sda3,18G,12G,6.0G,67%,/
6,/dev/sda1,297M,214M,84M,72%,/boot
7,tmpfs,182M,36K,182M,1%,/run/user/1000
```

**A better way with sed:**

```bash
df -h | awk 'NR>1' | awk '{print NR "," $0}' | sed -E 's/ +/,/g'
```

**Add the date and remove the percentage sign** (`$` in sed means the end of a line):

```bash
df -h | awk '{print NR "," $0}' | sed -E 's/ +/,/g' | sed -E 's/%//g' | sed -E "s/$/,$(date +%d-%m-%y)/g"
```

**Add the IP address.** You could extract it from `ifconfig` or `ip r l`, but `hostname -I` is simpler:

```bash
df -h | awk 'NR>1' | awk '{print NR "," $0}' | sed -E 's/ +/,/g' | sed -E 's/%//g' \
  | sed -E "s/$/,$(date +%d-%m-%y)/g" | sed -E "s/$/,$(hostname -I)/g"
```

**Add the hostname as well:**

```bash
df -h | awk 'NR>1' | awk '{print NR "," $0}' | sed -E 's/ +/,/g' | sed -E 's/%//g' \
  | sed -E "s/$/,$(date +%d-%m-%y)/g" | sed -E "s/$/,$(hostname -I)/g" | sed -E "s/$/,$(hostname)/g"
```

```console
1,/dev/sdb,251G,3.2G,236G,2,/,30-06-23,172.24.42.20 ,ahmadhassan
2,none,3.9G,4.0K,3.9G,1,/mnt/wsl,30-06-23,172.24.42.20 ,ahmadhassan
3,tools,475G,191G,284G,41,/init,30-06-23,172.24.42.20 ,ahmadhassan
```

> `hostname -i` (lowercase) returns the loopback address (`127.0.1.1`), so use `hostname -I` for the machine's IP.
